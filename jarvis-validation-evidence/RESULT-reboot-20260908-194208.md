## 所見 #7 を撤回 2026-09-08 20:00

「shared stream が入力経路変更に追従できない」は**新規所見ではなく、意図的な設計**。
`bin/shared_audio.py open_once()` に根拠コメントがある:

> Device-following off: a healthy stream is kept even if the OS default changes.
> Replacing a working stream would mean another open/start against CoreAudio,
> which is precisely the call that deadlocks -- so replacement is reserved for a
> stream that has actually failed (ensure_healthy_for_turn). The cost is that
> switching the preferred microphone while both devices are present is no longer
> picked up at the next turn; **it takes a runtime restart**.
> `self._rec.follow_default_device = False`

→ #7 は BACKLOG から削除。**仕様通りの挙動**であり、回復手順（runtime 再起動）も明記済み。
→ #8（無信号がユーザーに通知されない）は所見として残す。

## 切り分け結果（ユーザー実測）
- システム設定のレベルメーター: **`外部マイク` では振れる / `内蔵マイク` では振れない**
- ffmpeg で内蔵マイク直接測定も -91.0dB（無音）
- → 内蔵マイク（MacBook Proのマイク）のみが無音。外部マイク（ジャック）は正常。
- → handoff §15 Known Gap #7「internal mic DIGITAL_SILENCE」の再発と整合。

## 回復手順（source 変更なし）

   （まず内蔵を復活させたい場合はジャックから機器を抜いて再確認する価値あり。
